    Tokens and colour¶

    A token is a named value, such as a size or a colour. A designer picks the name. The code looks up the value. Both the web app and the native app read the same values, so a screen looks the same in both.

    The values live in design/tokens.json (sizes, type, timings) and design/colour.json (colour). The tables below are copied from them. If a table and the file disagree, the file is right.

    Units are pixels unless a table says otherwise.

    Scales¶

    Space¶

    The gap between things. Use these for padding, margins and gaps.

    Token px Use it for
    none 0 No gap
    2xs 2 The thinnest gap
    xs 4 Tight gaps
    sm 8 Gaps between neighbouring items
    md 12 Padding inside cards and fields, and medium gaps
    lg 16 Gaps between panels and the outer edge of the screen
    xl 24 Space between groups of items
    2xl 32 Space around a large section
    3xl 48 The biggest gap

    Radius¶

    How round a corner is.

    Token px Use it for
    sm 6 Small controls, such as tags and chips
    md 10 Buttons and small panels
    field 14 Text fields
    card 18 Cards
    island 24 Islands, the large panels that sit on the ground colour
    full 9999 Fully round: buttons, pills, small tags, and search and message fields

    Control heights¶

    Token px Use it for
    sm 32 Small buttons and controls
    md 40 Default buttons and controls
    lg 48 Large buttons and controls

    Fonts¶

    Token Family Use it for
    heading Bricolage Grotesque Titles, section headings and names
    body Figtree Everything else

    The web kit bundles the faces it uses and loads them with the new shell, not on the first page: Bricolage Grotesque 600 and 700, Figtree 400, 500 and 600, and Figtree 400 italic, so italic message text is a real italic, not a slanted upright.

    Text styles¶

    Pick a text style. Do not set a size or weight by hand. Size and line are in px. Weight is a plain number (400 is normal, 700 is bold).

    Style Font Size Line Weight Use it for
    title heading 20 26 700 The title of a screen or panel
    section heading 15 20 600 Section headings
    name heading 15 20 700 People's names and room names
    body body 15 22 400 Normal text, such as message text
    bodyStrong body 15 22 600 Normal text that needs emphasis
    meta body 13 18 400 Secondary details such as times and counts
    small body 12 16 400 Small print and captions
    tag body 11 16 600 Labels inside small tags

    Shadows¶

    Alpha is the opacity of black, from 0 (clear) to 1 (solid). Dark mode uses Alpha; light mode uses Alpha (light), because the same black is far heavier on a light surface.

    Token x y Blur Alpha Alpha (light) Use it for
    island 0 6 24 0.35 0.08 Islands
    overlay 0 24 64 0.6 0.18 Things that float above the screen, such as dialogs and menus

    Timings¶

    In milliseconds.

    Token ms Use it for
    fast 120 Small changes, such as a hover or a press
    base 200 Most changes
    slow 320 Large changes, such as a panel opening
    typeahead 1000 How long typed letters in a list add up before they start again
    toast 4000 How long a toast stays
    toastAction 8000 How long a toast with an action, or a danger toast, stays

    The last three are not animations. They are how long something waits, and the Behaviour chapter uses them.

    Breakpoints¶

    The screen width, in px, at which the layout changes.

    Token px Meaning
    phone 600 Below this width a screen uses its phone layout
    narrow 1024 Narrow width
    docked 1200 Wide enough for a side panel to stay open beside the content

    The Layouts chapter says what changes at each width.

    Layout widths¶

    Token px Use it for
    gutter 16 The gap between islands and the padding around the screen
    leftColumn 288 Width of the left column
    rightColumn 264 Width of the right column
    dock 60 Height of the dock, the rounded bar of pinned communities
    dialogSm 400 Widest a small dialog gets (a confirmation)
    dialogMd 560 Widest a medium dialog gets (one with a form)

    Icon sizes¶

    The size of an icon, in px. Pick the size that matches the text beside it.

    Token px Use it for
    xs 14 Icons inside tags and the densest rows
    sm 16 Icons beside small text
    md 18 Default icons beside text and inside buttons
    lg 20 Icons in toolbars and section headings
    xl 24 Large icons, such as in an empty state or a navigation item

    Avatar sizes¶

    The diameter of an avatar, in px, for a person or a community.

    Token px Use it for
    xs 20 Avatars inside a line of text or a dense list
    sm 28 Avatars in a stack, or beside small text
    md 36 The default avatar in a member row or a message
    lg 44 Avatars in a card or a header
    xl 64 A profile or a community header

    Borders and rings¶

    The width of a border, and of the focus ring, in px.

    Token px Use it for
    hairline 1 The thin line around islands, cards and fields
    selected 2 The border of a selected item
    focus 2 The focus ring, which shows where the keyboard is
    focusOffset 2 The gap between a control and its focus ring

    State layers¶

    Hover and pressed are not separate colours. A control shows them by mixing the text colour over its own background at the alpha in the table: use hoverOnFill and pressedOnFill when the background is accent or danger. Disabled is the opacity of a disabled control.

    Token Alpha Use it for
    hover 0.04 A pointer resting over a control
    pressed 0.08 A control being pressed
    hoverOnFill 0.16 A pointer over a control filled with accent or danger
    pressedOnFill 0.24 A control filled with accent or danger, being pressed
    disabled 0.5 A disabled control

    Touch density¶

    A density is a second set of values for some of the names above, for one kind of input. density.touch is for clients you use with a finger. It makes controls and rows bigger, so every press lands on something at least 48 wide and high, which is Android's minimum. Spacing, radii and text sizes stay the same in every density, so a touch screen has the same rhythm, only with taller controls.

    The Android app uses it everywhere. The web keeps the pointer values above and reaches the touch minimum another way: on a coarse pointer, a small button keeps its look and gets a bigger hit area (see Button in Components).

    Token Touch value Pointer value Use it for
    control.sm 40 32 Small buttons and controls
    control.md 48 40 Default buttons and controls
    control.lg 56 48 Large buttons, and text fields
    listRow.md 56 40 (control.md) The least height of a list row
    listRow.lg 72 48 (control.lg) The least height of a large list row, such as a person with a second line
    hitArea 48 — The smallest area a press counts in, whatever the control draws

    density.touch.control must have exactly the keys of control; the generator checks this.

    Colour¶

    The three inputs¶

    Every colour on a screen comes from a palette. The app makes the palette from three inputs:

    1. Base colour. One colour, chosen by the person using the app. It sets the accent and the hue of the greys.
    2. Mode. Dark or light.
    3. Intensity. Minimal, balanced or vibrant. It sets how strongly the base colour tints the greys (see "What intensity changes").

    A screen never uses the base colour directly. It uses the roles below. The palette turns each role into a real colour.

    The 16 roles¶

    Role What it is for What it may sit on
    ground The background behind the islands Nothing. It is the bottom layer
    surface Islands and panels ground
    fill The soft fill for cards, fields and hover ground or surface
    hairline Thin borders and the border of a popover any of the three
    text Normal text ground, surface or fill
    textSecondary Less important text ground, surface or fill
    textDim Icons and offline states. Dim text ground or surface only, never fill
    accent The selected item and primary buttons ground or surface
    onAccent Text and icons on top of accent accent only
    accentText Text that is accent-coloured ground, surface or fill
    focus The focus ring, which shows where the keyboard is ground, surface or fill
    positive Good, online or speaking ground, surface or fill
    warning Take care ground, surface or fill
    danger Error or destructive action ground, surface or fill
    onDanger Text and icons on top of danger danger only
    scrim The dim layer behind an overlay such as a dialog or sheet On top of the whole screen. It is see-through

    Use text on accent and danger only through onAccent and onDanger. Use accentText, not accent, when you want accent-coloured text.

    What the palette promises¶

    The palette checks these contrast ratios when it is made. Contrast is the difference in brightness between two colours. 4.5 is the usual minimum for readable text.

    Role Promise
    text At least 4.5 on ground, surface and fill
    textSecondary At least 4.5 on ground, surface and fill
    textDim At least 4.5 on ground and surface (not fill)
    accentText At least 6.9 on ground, surface and fill
    accent At least 3.0 on ground and surface, and onAccent reaches at least 4.5 on it
    focus At least 3.0 on ground, surface and fill
    positive, warning, danger At least 4.5 on ground, surface and fill. For danger, onDanger is the clearer of the two ink colours on it
    onAccent, onDanger At least 4.5 on accent and on danger. Each is the better of two colours, one dark and one light

    The scrim has no contrast promise. It only dims what is behind it.

    The palette keeps these promises for every base colour, both modes and all three intensities. You do not need to check them. You do need to keep each role on the backgrounds listed in the table above, because the promise only covers those.

    What intensity changes¶

    Intensity sets how much of the base colour tints ground, surface, fill and hairline. At minimal they are close to plain grey. At vibrant they carry a clear tint of the base colour. The tint multipliers are 1 for minimal, 2.5 for balanced and 5 for vibrant.

    Intensity tints only ground, surface, fill and hairline. The other roles keep their own lightness, nudged only as far as needed to keep their contrast on the tinted backgrounds. (A very dull base colour gives less tint at every intensity.)

    People colours¶

    Each person's avatar has a colour of its own, picked from their user id. It is the same on every screen, in both modes, for every base colour and intensity, and in both clients. The nine colours are in design/colour.json under people.colours:

    # Colour # Colour # Colour
    0 #FF8FB8 pink 3 #A6D36A lime 6 #6FB1F5 blue
    1 #FFA366 orange 4 #5FD49A green 7 #9AA0FF indigo
    2 #E0C060 yellow 5 #5ED1D1 teal 8 #C792F0 purple

    A person's colour is entry fnv1a32(id) mod 9. fnv1a32 is 32-bit FNV-1a over the id's UTF-8 bytes: start at 0x811C9DC5, and for each byte XOR it in and multiply by 0x01000193, modulo 2^32. The id is used exactly as the API sends it. A missing or empty id gives no colour (the neutral fill). The web kit's personColour(id) does this, design/gen/colour_ref.py is the reference, and design/vectors/person-colour.json holds the test vectors every client must match.

    The list is frozen. Never change, add, remove or reorder a colour: every person would change colour. The generator refuses any other list.

    All nine take the dark initials at 4.5:1 or more in both modes, so the Avatar shows them exactly as listed.

    Rules¶

    1. Never write a hex colour or a pixel number on a screen. Pick the role or the token by name.
    2. A colour need with no role goes through Extending the system. Do not pick a close colour. Ask for the role to be added.
