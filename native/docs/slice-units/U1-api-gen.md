# U1: REST and socket code generator

Read `_rules.md` here first. Work in `native/`.

## Goal

From the pinned contract, generate pure-Rust wire types and a REST client that survive a newer
server, repeatably, with one command.

## Owned paths

`tools/gen-api/`, `crates/semaphore-wire/`, `crates/semaphore-api/`, `scripts/gen-api.sh`,
`scripts/check-core-boundary.py`, the `reqwest` line in `Cargo.toml`, and whatever `Cargo.lock`
and `deny.toml` then need. `crates/semaphore-net/` only as far as the reqwest bump requires.

## Inputs

- `contract/openapi.json`: OpenAPI 3.0.0, 238 operations, 295 schemas, 34 named enums.
- `contract/socket-events.json`: 45 server and 11 client events, each with `payload` and maybe
  `ack`, as `$ref`s into `openapi.json`. `subscribeAll` has no payload.
- `contract/wire-contract.md`: the reader rules this must satisfy. Read them.
- Recorded real payloads: `git show "$(sed -n 's/^commit=//p' contract/PIN):frontend/src/__tests__/fixtures/message-wire-payloads.json"`.
  Copy them to `crates/semaphore-wire/tests/data/`.

## Build this

**`tools/gen-api`:** a Rust binary excluded from the workspace (`tools` already is), with its own
`Cargo.lock`, using the `progenitor` library 0.15.1, not the CLI, because the CLI needs nightly
rustfmt. Run the output through stable `rustfmt --edition 2024`.

**Steps, in order:**

1. Strip `multipart/form-data` request bodies, as `wire-contract.md` shows.
2. Generate. Use `GenerationSettings::with_replacement` to point each of the 34 named enums at a
   tolerant type generated by this tool. That API is from memory, so check it first. If it doesn't
   exist or doesn't work, use `syn` to rewrite the generated enums instead, and say so in your report.
3. **Tolerant enum.** Every named enum gets an `Unknown` variant holding the raw value: `Unknown(String)`,
   or `Unknown(i64)` for the integer enum `ReplayDurationMinutes`. It deserializes any value and
   serializes back exactly what it read. `as_str()` returns the wire string.
4. Split the output with `syn`: `pub mod types` goes to `semaphore-wire/src/generated.rs`, the client
   to `semaphore-api/src/generated.rs`, using `semaphore_wire as types`. Mark each file
   `// @generated` with `#![allow(clippy::all)]` or equivalent.
5. From `socket-events.json`, generate `semaphore-wire/src/events.rs`:
   - `enum ServerEvent` with one variant per server event holding its payload type, plus
     `Unknown { name: String, payload: Value }` and `Malformed { name: String, payload: Value, error: String }`.
   - `ServerEvent::decode(name: &str, payload: Value) -> ServerEvent`, which never fails.
   - A `const` for each client event's name, plus one function per client event returning its
     payload as a `Value`, typed by its payload, and a generated type alias for its ack.

**`semaphore-wire`:** depends only on `serde`, `serde_json`, `chrono` (no default features), `uuid`,
`regress`, and whatever else the generated code needs that is pure Rust.

**`semaphore-api`, hand-written files:**

- `src/error.rs`: `ApiError { status: u16, code: ErrorCode, message: String, retryable: bool, retry_after_ms: Option<u64> }`,
  and `async fn from_progenitor(error: Error<()>) -> ApiError`. Only 1 of 238 operations declares
  its error, so read `ErrorResponseDto` from the unexpected response's body. `message` is a string
  or a list of strings. A body that won't parse gets `ErrorCode::Unknown("UNKNOWN".into())`
  with the HTTP status, and retryable only for 502, 503 and 504.
- `src/upload.rs`: `POST /api/file-upload` as multipart: `file`, `resourceType`, optional `resourceId`.
  It returns `FileUploadResponseDto`.
- `pub use reqwest;` so `semaphore-net` builds the client with the same version.

**The reqwest conflict:** progenitor-client 0.15.1 needs reqwest 0.13; the workspace pins 0.12. Move
the workspace to 0.13. `semaphore-api` takes no TLS feature. `semaphore-net` takes TLS, and must
still compile. Prefer rustls on `ring`, which the lock already has, over adding `aws-lc`, and make
sure `cargo deny check` passes. Report what you chose and why.

**`scripts/check-core-boundary.py`:** make it check `semaphore-wire` as well as `semaphore-core`,
for the same rules. Don't weaken any rule.

**`scripts/gen-api.sh`:** runs the generator in the image. `--check` regenerates to a temp directory,
fails on any difference, and also runs `scripts/pin-contract.sh --check`.

## Tests, in `crates/semaphore-wire/tests/`

1. Every recorded payload decodes, with no `Malformed`.
2. A `MessageDto` with a span of type `HOLOGRAM`: the message decodes, `SpanType::Unknown("HOLOGRAM")`
   is kept, and it serializes back unchanged.
3. A `MessageDto` with an extra unknown field decodes.
4. A required nullable field (`MessageDto.replyTo`) that is missing decodes as `None`, like `null`.
5. `ServerEvent::decode("someFutureEvent", json!({}))` is `Unknown`. A `newMessage` with a wrong-typed
   required field is `Malformed` and doesn't panic.
6. Each of the 45 server events has a variant. Check this by reading `contract/socket-events.json`.
7. `ErrorCode` accepts a code this build has never seen.

In `crates/semaphore-api/tests/`: `from_progenitor` against an in-process HTTP server, for a real
`ErrorResponseDto` body with a string `message`, one with a list, and an unparseable body.

## Proof

```bash
scripts/gen-api.sh --check
scripts/in-image.sh cargo test --locked -p semaphore-wire -p semaphore-api
scripts/in-image.sh python3 scripts/check-core-boundary.py
scripts/in-image.sh cargo check --locked -p semaphore-wire --target aarch64-linux-android
scripts/in-image.sh cargo check --locked -p semaphore-wire --target aarch64-apple-ios
scripts/in-image.sh cargo deny check
scripts/verify.sh
```
